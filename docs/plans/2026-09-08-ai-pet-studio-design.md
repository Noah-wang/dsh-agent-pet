# AI Pet Studio design

## Goal

Add an in-app studio to `dsh-agent-pet` that turns a short description into a
high-quality transparent pet image. The generated pet immediately replaces the
default avatar and continues to react to the six existing DSH agent states.

## Chosen approach

The first release uses OpenAI's Image API through a small provider adapter. The
model, API base URL, quality, and credential reference stay configurable; the
default model is `gpt-image-2`. DSH's Host credential service resolves
`OPENAI_API_KEY` for each generation request, so secret material never enters
browser state, API responses, logs, settings files, or exported pet metadata.

The client contributes a modal through the existing `shell.overlay` entry. It
collects a name, visual description, and style preset, then calls an
authenticated DSH Connection fetch route. The host validates the request,
allows only one generation at a time, adds a production-oriented pet prompt,
and calls the configured image provider. Only a valid bounded PNG response is
accepted.

Generated bytes and public metadata are written atomically below the configured
DSH data directory. The active avatar route serves either that PNG or the
packaged SVG fallback. Resetting removes the generated selection without
affecting the packaged default. The six state-specific CSS motions remain the
animation layer for this release; a later release can add generated multi-frame
sprite rows without changing the studio or provider boundary.

## Safety and limits

- Generation is an explicit button action and may incur provider charges.
- Prompt, name, request body, response body, and PNG byte lengths are bounded.
- Only PNG output with a correct signature is stored; generated SVG/HTML is not
  accepted or executed.
- API errors are reduced to bounded user-facing messages and never include the
  key.
- The host uses DSH's authenticated Connection routes rather than raw writable
  web-server endpoints.
- Concurrent generation is rejected with `409`; a request timeout prevents a
  stuck provider call from holding the lock indefinitely.

## Verification

Unit tests cover request normalization, prompt construction, provider success
and error handling, PNG validation, atomic storage, reload, and reset. The
existing state/config tests remain green. The final package is syntax-checked,
packed, unpacked into a clean directory, and visually checked in DSH Web.
